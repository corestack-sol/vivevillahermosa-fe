## 4. Health-check — el frontend ya expone uno, recomendamos que el backend también

Agregado hoy: `GET /api/health` en este repo (Next.js) — hace ping a `GET /propiedades?perPage=1` del backend y reporta `ok`/`degraded` con latencia. Es un parche mínimo (ver `docs/PLAN-AUDITORIA-FASE1-MVP.md` hallazgo #14), no monitoreo real.

**Recomendación, no bloqueante:** si el backend (NestJS) no tiene ya un endpoint de salud propio (`GET /health` o similar, típico en NestJS con `@nestjs/terminus`), vale la pena agregarlo — el health-check del frontend depende de que el backend responda, pero no sustituye que el backend sepa reportar su propio estado (conexión a base de datos, etc).

Es la misma cuenta/proyecto de PostHog que ya se está usando en el frontend (incluye eventos + errores en un solo lugar) — evita levantar Sentry aparte.
